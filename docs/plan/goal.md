# プロジェクトの目的・完成形

## 概要

**Clip Manager** は、YouTube などから動画クリップをローカルへダウンロードし、
ダウンロード済みのクリップを **一元的に管理・視聴** できるデスクトップアプリである。

ベースは [clip-downloader](https://github.com/ysm446/clip-downloader)
（PySide6 + yt-dlp + ffmpeg）。そのダウンロード機能を **内包** したうえで、
「ダウンロードした後の体験」＝**ファイル管理機能**を中核として追加する。

## 重視する価値

1. **ダウンロードから視聴まで一つのアプリで完結する**
   - 別のファイラ・別のプレイヤーを開かなくてよい。
2. **クリップが増えても迷子にならない**
   - フォルダ・タグ・検索で目的のクリップにすぐ辿り着ける。
3. **メタデータと実ファイルの整合**
   - DB が指す実ファイルが消えていれば気付ける（欠落検知）。
4. **既存資産の尊重**
   - clip-downloader の設計（QThread + Qt Signals、yt-dlp Python API、
     コーデックを必須フィルタにしない方針）をそのまま踏襲する。

## ライブラリという単位

- **ライブラリ＝ユーザーが指定したルートディレクトリ**。複数登録でき、
  UI でアクティブなライブラリを切り替えられる。
- 各ライブラリは **自分のメタデータDB（SQLite）をルート直下に持つ**ため、
  フォルダごと移動・コピー・別PCへ持ち出しても管理情報が一緒に動く（可搬性）。
- 「仕事用」「学習用」「アーカイブ」のように、用途別にライブラリを分けられる。

## 完成形（ユーザーから見た姿）

- アプリを開くと、選択中の **ライブラリ**（ダウンロード済みクリップの一覧）が
  表示される。ライブラリは画面上から追加・切替できる。
- 一覧は **サムネイル / 詳細（表）** で切り替えられ、タイトル・画質・長さ・
  サイズ・追加日などが分かる。
- 左側の **フォルダ／タグツリー** と上部の **検索ボックス** で絞り込める。
- クリップを選ぶと **アプリ内プレイヤー** で再生でき、字幕も扱える。
- 右クリック等から **リネーム・移動・削除・タグ付け** といった
  ファイル操作・整理ができる。
- 「ダウンロード」画面から従来どおり URL を入力して取得でき、
  取得したクリップは自動でライブラリに登録される。

## 対象機能（合意済みスコープ）

| 区分 | 内容 |
| --- | --- |
| ライブラリ一覧 | サムネイル/詳細表示、メタ情報の閲覧 |
| 整理 | フォルダ分け、タグ付け、カテゴリ |
| 検索・絞り込み | タイトル・タグ・画質・日付などで検索/フィルタ |
| ファイル操作 | リネーム・移動・削除・複製 |
| メディア | **アプリ内プレイヤー内蔵**（QtMultimedia） |
| ライブラリ | **複数のルートディレクトリ**を登録・切替。DBはルート直下に自己完結 |
| データ保存 | クリップのメタデータは **SQLite**（ライブラリごとに1つ）で管理 |

## 将来構想（現スコープ外・後続で対応）

- **ローカルLLM による動画分析**
  （[video-content-analyzer](https://github.com/ysm446/video-content-analyzer)
  のような、字幕生成・翻訳・シーン解析・タグ付け・Q&A など）。
  - GUI は **PySide を継続**する（ML/LLM は GUI 非依存の Python なので、
    Electron へ移行する利点はない）。
  - 推論は **GUI と分離したワーカー/プロセス**で実行する（詳細は plan.md）。
  - モデルは `models/`、llama.cpp サーバ等のランタイムは `runtime/` に置く。
    **llama.cpp はアプリ内ダウンロードUIで取得・バージョン管理**できるようにする。
  - 分析結果（タグ・要約・チャプター等）は、ライブラリの SQLite メタデータに
    取り込んで検索・整理に活かす。

## 非対象（現時点では作らない）

- 複数 PC 間の同期 / クラウド連携
- 動画編集（トリミング・結合など）
- YouTube 以外のサイト個別対応の網羅（yt-dlp が対応する範囲に委ねる）
